# 可选 OSC 阻抗输出

主仓库 Pink 算法/参数、绝对 TCP 输入和最终安全门保留。
`motion/osc_impedance.py` 负责 MIT 参数及前馈，
`motion/osc_impedance_reference.py` 是唯一 MIT 参考状态维护模块，
`nero_backend/osc_impedance.py` 负责 MIT 模式交接和发送校验。
MIT 与 CPV 共用 `HardwareTxOwner` 的容量一邮箱、epoch、generation 撤销、
发送结果和唯一 CAN 写入线程；没有第二条硬件发送链。
真机普通 TCP 更新沿用 CPV 策略：保留目标代次更新，不在收到目标时撤销 MIT 待发命令。
新控制命令计算完成后覆盖单槽邮箱；发送前和逐关节检查只使用显式停止/权限屏障，
不把“输入目标代次更新”当作撤销依据。HOLD、停止、故障、急停、会话结束和
模式/权限交接仍严格撤销；新鲜度、安全门、MIT 参考维护及 200 ms 上限保持原样。
该调整不定义“摇杆松开即 HOLD”：摇杆松开后的输入语义及参考生成均未修改。
发送线程按高精度起始间隔推进参考并提交整批成功状态；失败不提交，
故障锁定当前 epoch，不自动重试。OSC 读取快照，不积分或回写 MIT 参考。
MIT 下 Pink 从参考快照规划，实测位置仍用于安全门、重力和到达判断。
CPV 的位置生成不变，仅控制间隔改为高精度计算；既有时间戳不全局替换。

## 选择与启动

Web 上的“原控制 CPV / 阻抗控制”按钮只选择下次启动的输出。
也可 `POST /api/osc/output-mode`，请求为
`{"mode":"impedance","client_id":"当前客户端身份"}`；`mode` 也可为 `cpv`。
真机必须已确认 HOLD，独立关节反馈新鲜且停稳；IDLE 本身不代表 HOLD，
断线及 FREEDRIVE 不允许切换。影子会话允许 IDLE 或停稳 HOLD_READY。
运行、制动、故障、交接、活动任务/租约均拒绝。
已有会话被结束并撤销目标；切换不会自动运动或恢复旧目标。
前端按钮只调用 OSC 接口，是否可切换使用 `output_switch.allowed/reason`。
网页摇杆依据通用会话身份和权限 epoch 失效清除锚点，不判断输出模式；
选择当前模式不结束会话，切换拒绝也不主动重置摇杆。

选择原子保存到 `runtime/osc_output_mode.json`，首次默认 CPV。
配置损坏时回退 CPV，原因在状态的 `output_switch.selection_error` 中；
重新选择 CPV 可修复保存文件。重启恢复选择不会启动会话或发送硬件命令。
硬件退出或保存失败时不改变选择、不恢复旧目标。

状态新增 `output_mode`、`output_switch`、`impedance`。
`impedance.command` 为最新计算命令，实际发送结果仍在
`transport.cpv_mailbox.last_success`（保留兼容字段名）中，包含发送前馈、参考及输出模式。
`torque_diagnostics` 分别给出弹簧、阻尼、前馈和估算总力矩，不是实测总力矩。
`execution_sample.motor_feedback` 提供已有 RX 缓存的电流、SDK 力矩估计和逐轴新鲜度；
SDK 力矩由电流拟合，不是独立力矩传感器，估算项也未模拟协议增益量化。
`impedance.last_mode_entry` 记录首帧实测锚点与新的模式反馈。

## LX 提取范围与假设

MIT 退出不使用 `set_follower_mode()`：SDK 的该调用保留运动模式，不能退出 MIT，
且会修改反馈推送/主从配置。阻抗退出专用路径先清除 MIT 弹簧参考，显式请求
CPV，再等待新的 `ctrl_mode=1 / mode_feedback=5`，随后用新鲜实测关节位置发送
七轴 CPV 保持帧并确认停稳；不选择 P/J，不恢复任何历史 CPV 目标。
缺少 CPV SDK 支持、模式反馈未更新、保持帧失败或未停稳均保持 FAULT，禁止正常输出。
MIT 专用退出预算覆盖模式确认和前后两次停稳反馈读取；CPV 的原预算不变。
该退出顺序仅完成软件及模拟硬件验证，仍需现场确认及实机验收，不能据此清除现场 Fault。

- 七关节 kp=3.5、kd=0.3；MIT 的 q_d、dq_d 同取发送参考维护器最终结果，
  dq_d 不使用原始 Pink 速度。普通跟踪步满足 q_d[k] = q_d[k-1] + dq_d[k] × dt；
  首帧、重新锚定及 HOLD 保持实测锚点/已有保持参考，dq_d=0。
  构建器中的零速度仅为待最终整形的占位值；真机与影子发送均覆盖为最终参考速度。
  阻尼诊断与影子动力学使用 kd × (dq_d - dq_actual)，不改变独立摩擦项。
- 重力映射、有效性检查、限幅、变化率限制来自 LX 的 `mit_dynamics.py`。
- 使用主仓库同一 URDF、关节约定和隔离 `.conda/nero-kinematics/python.exe`。
- LX 跟踪配置使用 bare_flange、倍率 1.3、alpha_ramp_s=5，忽略夹爪与负载质量。
  **这不是带夹爪/负载的精确动力学模型，不得将仿真当作负载安全证明。**
- 与 LX `first_frame_gravity=fresh` 一致，alpha 初始即为1.3；
  硬件首帧 dt=0，因此新鲜重力模型有效，但发送力矩为零；
  随后每关节以100 Nm/s进入目标，绝对限幅16 Nm（v120）。
  没有新增在线调参入口；alpha 不发生改变时无需倍率渐变。
- 新结果最大60 ms；允许至100 ms的短期缓存，两者的模型姿态与实测关节角度差均不超过0.2 rad。
  此阈值单位为角度 rad，不是速度 rad/s；首帧预热仍要求姿态差小于0.02 rad。
  不可用结果触发停止，不以静默零前馈继续运动。
- 硬件发送前及每关节发送时再检查反馈150 ms、重力100 ms、epoch与目标撤销。

未提取 LX 完整 OSC、静态 IK、手动托举、摩擦补偿、实验调参或控制链配置切换。
默认 CPV 不导入阻抗模块、不启动重力进程，原 TCP 请求格式保持兼容。

## HOLD / 退出

输入 HOLD 先撤销旧请求，用新鲜实测位置重锚，清除旧弹簧偏差；
之后保持该锚点，不每周期跟随实测重建。实际关节停稳才进入 HOLD_READY。
操作员结束会话和故障的 P0 退出先尝试新鲜实测锚定 MIT 帧，再显式请求 CPV，
要求新的 CPV 模式反馈，然后发送实测位置保持帧并确认停稳；未确认模式时禁止 CPV 帧。
PICO 松 Grip 的输入 HOLD 保留会话及新保持锚点，只刷新有效重力；
这与操作员结束控制的 HOLD 区分，下一次输入不会复活旧目标。
停止先结束输出线程，再退出硬件模式，最后关闭重力进程。
Follower 是角色请求，不等于已退出 MIT，不用于阻抗运动模式退出。
现有请求顺序仍需实际固件确认；保持帧失败、退出未确认或关节未停稳都不能
宣称停止成功，禁止重新开始正常 CPV/MIT 输出。
不增加“误差大且速度低就停止”的规则；自由空间明显跟踪残差仍是验收失败。

## 固件能力核验与两阶段预算

第一阶段仅软件修复、前馈限制和总力矩诊断，不建立新的纠正力矩限值。
已查本地官方 SDK：v120 的 MIT 编码继承 v111，前馈编码范围为全轴 ±16 Nm，
`T = kp*(p_des-p) + kd*(v_des-v) + t_ff`，SDK 对编码参数限幅。
这些不是总力矩保护证据，更不是人机交互安全限值；API 查询 timeout 也不是命令 watchdog。

尚未确认：固件总力矩/电流阈值、MIT 命令超时及超时后动作、总力矩变化率限制、
MIT 下通用碰撞/关节限制是否有效、无运动退出顺序和反馈语义。
第二阶段须据实际固件资料/厂家确认及真实负载制定逐轴预算，不自动改增益、
倍率或切换纯力矩控制。资料缺失不阻止软件/离线测试，但阻止未经确认的实机验收。

MIT 使用明确标注的 PD 力矩替身，不是完整机械臂动力学。

离线脚本默认显式名义物理倍率 1.3，与现有前馈标定匹配；实际影子默认物理倍率 1.0，
可用第二条命令检查不匹配。两者均不是对真实负载的测量或校准。
该替身在零力矩首帧后的前馈爬升期间会发生启动偏移（首次测量约37 mm），
不能将此数字外推为实际硬件位移，也不能据此宣称实机无瞬态。

实机验收必须先确认现场可运动：CPV、阻抗、切回 CPV，
各沿基座 X 做2 mm往返并手动 HOLD，仅停稳后切换。
记录反馈模式、实测 TCP、关节、首帧、发送结果与力矩。
出现超范围位移、模式错误、反馈/重力过期或新故障立即 HOLD，
不增加位移范围或自行调参。尚未进行实机测试时不得声称全部验收通过。
