# 数据采集

采集器位于 HTTP 进程，经公共 OSC 只读接口取得数据；不持有 CAN 写权限，
不依赖 PICO、网页摇杆或策略模型，不改变 Pink、CPV、MIT 和停止逻辑。

## 三条独立原始流

| 文件 | 内容 | 频率 |
| --- | --- | --- |
| `raw/osc_inputs.jsonl` | OSC 入口的完整命令 payload、会话/客户端、来源、输出模式、时间戳及接收结果 | 逐条事件，不重采样 |
| `raw/robot_states.jsonl` | 实测关节、速度、夹爪、实测/目标 TCP、反馈 revision 和控制样本标识 | 目标 50 Hz |
| `raw/camera_frames.jsonl`、`raw/images` | 外部/腕部 RGB，独立保存和打时间戳 | 每路目标 20 Hz |

`track_tcp` / `move_tcp` 在 OSC 入口已是**基座坐标系绝对位姿**：XYZ 单位 m，
旋转为 XYZW 四元数。适配器内部的 delta、手柄消息、摇杆事件、推理 action chunk
不属于该采集流。HOLD、停止、FREEDRIVE 和夹爪命令同样保留；心跳不作为运动输入。
`accepted` 只代表 OSC 接口接收结果，不代表硬件已发送或跟踪成功。

OSC 入口只写内存环形历史；独立记录线程落盘，避免给控制路径增加文件 I/O。
历史溢出、采集异常与反馈/相机丢帧明确显示并写入质量诊断，不静默跳过。

## 来源与连接

来源绑定在真实 OSC 会话上，而不是由采集按钮的前端选项决定。
会话启动的可选 `input_source` 默认为 `external`；现有适配器绑定 `web`、`pico`、`pi05`。
新控制源使用相同 OSC 会话/心跳契约和自己的来源标识即可，不需修改采集器。
设备适配器的特有连接状态在 AdapterRuntime 中归一化为同一连接契约。

启动必须有有效 ACTIVE 会话和连接：所有来源检查会话有效性/心跳；
已知设备适配器还核对其连接/运行状态及会话身份。旧客户端若显式传入
`control_source`，必须与实际来源一致；省略时直接使用实际来源。

`episode.json` 保留起始来源、session/client、真机/影子、CPV/阻抗、连接状态变化历史，
以及输入事件中观察到的来源/输出模式。采集中失联会提示并保留连接变化，
不会仅因控制源结束连接就丢弃仍然有效的机械臂反馈；换会话或输入历史丢失会使
质量审计失败，但仍保留原始证据。采集器不会自动恢复运动。

## 相机可选与质量

零路或一路相机仍可开始、正常保存；无画面以黄色提示，不假装存在双 RGB 数据。
采集开始时固定本次可用相机集合；原始 RGB 规格仍为 640×480。
完整双 RGB 训练视图仍需另行满足双相机、频率、时间对齐等条件。
无相机的有效原始记录不会因缺双 RGB 被丢弃，但 `training_eligible` 保持 false，
并明确记录 `dual_rgb_unavailable`。所有训练视图、FK、动作重建和 H16 均在离线后处理。

Web 显示目标/实际采样频率、逐路 RGB 频率、相机/状态丢帧及 OSC 输入缺口。
丢帧或低频使用红色高亮；没有相机是黄色警告，不当作丢帧。
